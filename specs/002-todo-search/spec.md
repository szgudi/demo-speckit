# 功能规格：Todo 搜索与筛选

**功能编号**：002-todo-search  
**状态**：草案  
**创建日期**：2026-08-26  
**输入来源**：`需求.md`、`.specify/memory/constitution.md`、`specs/001-todo-list/spec.md`、`setup.txt`

## 1. 目标与范围

在既有单用户 Todo List 的基础上，提供按标题关键词搜索和按完成状态筛选的能力，帮助用户从较长的待办列表中快速找到目标事项。本迭代只扩展查询与展示能力，不改变 Todo 的新增、编辑、完成/恢复和删除规则，也不引入用户账户或多列表模型。

搜索和筛选结果必须来自后端通过 MySQL 查询得到的数据。用户刷新页面后，当前查询条件是否保留不作持久化要求；页面重新打开时默认显示全部待办。

## 2. 用户故事与验收场景

### 用户故事 1：按标题关键词搜索

作为一名用户，我希望输入标题中的关键词，以便快速找到相关待办。

#### 验收场景

1. **搜索匹配的待办**
   - **假如** 系统中存在标题包含“采购”的待办
   - **当** 用户在搜索框输入“采购”并提交或等待搜索生效
   - **那么** 列表只显示标题中包含该关键词的待办
   - **并且** 每条结果仍显示完整标题和完成状态

2. **搜索不区分英文字母大小写**
   - **假如** 系统中存在标题为“Review API”的待办
   - **当** 用户搜索“review”或“REVIEW”
   - **那么** 该待办都应被匹配

3. **关键词首尾空白被忽略**
   - **假如** 用户输入的关键词首尾包含空白字符
   - **当** 系统执行搜索
   - **那么** 系统按去除首尾空白后的关键词进行匹配

4. **清空关键词显示全部待办**
   - **假如** 用户已输入关键词并得到搜索结果
   - **当** 用户清空搜索框，或输入仅包含空白字符的内容
   - **那么** 系统移除关键词条件并显示全部待办
   - **并且** 结果仍遵循既有的状态优先、同状态按创建时间从新到旧的排序规则

5. **无匹配结果**
   - **假如** 没有待办标题匹配用户输入的关键词
   - **当** 搜索完成
   - **那么** 系统显示中文的“没有找到匹配待办”空结果提示
   - **并且** 页面仍保留搜索关键词和清除搜索的操作

### 用户故事 2：按完成状态筛选

作为一名用户，我希望只查看未完成或已完成的待办，以便专注于当前需要处理的事项或复查已完成记录。

#### 验收场景

1. **筛选未完成待办**
   - **假如** 系统中同时存在未完成和已完成待办
   - **当** 用户选择“未完成”筛选条件
   - **那么** 列表只显示未完成待办

2. **筛选已完成待办**
   - **假如** 系统中同时存在未完成和已完成待办
   - **当** 用户选择“已完成”筛选条件
   - **那么** 列表只显示已完成待办

3. **恢复全部状态**
   - **假如** 用户已选择“未完成”或“已完成”
   - **当** 用户选择“全部”筛选条件
   - **那么** 列表显示符合当前关键词的全部待办

4. **筛选无结果**
   - **假如** 当前状态条件下不存在待办
   - **当** 筛选完成
   - **那么** 系统显示中文空结果提示，并明确当前筛选没有匹配项
   - **并且** 系统不把该状态误报为系统读取失败

### 用户故事 3：组合搜索与筛选

作为一名用户，我希望同时使用关键词和完成状态条件，以便更精确地定位待办。

#### 验收场景

1. **组合条件按交集匹配**
   - **假如** 系统中存在标题包含关键词但状态不同的多条待办
   - **当** 用户输入关键词并选择一种完成状态
   - **那么** 列表只显示同时满足标题关键词和状态条件的待办

2. **修改任一条件重新查询**
   - **假如** 页面已经显示组合条件的结果
   - **当** 用户修改关键词或完成状态
   - **那么** 系统使用最新的两个条件重新加载结果
   - **并且** 不应继续显示上一组条件中已经不匹配的待办

3. **在筛选结果中执行既有操作**
   - **假如** 搜索结果中存在待办
   - **当** 用户完成、恢复、编辑或删除其中一条待办
   - **那么** 操作按照既有 Todo 规则执行
   - **并且** 操作成功后，列表重新按当前搜索条件计算；不再匹配的待办从结果中移除

### 用户故事 4：查询过程中的反馈与恢复

作为一名用户，我希望知道查询是否正在进行以及失败后如何恢复，以便不会误解列表状态。

#### 验收场景

1. **显示查询加载状态**
   - **假如** 用户提交新的关键词或筛选条件
   - **当** 后端查询尚未完成
   - **那么** 页面显示加载状态，并避免把暂时没有结果误显示为空状态

2. **查询失败可重试**
   - **假如** 搜索或筛选请求失败
   - **当** 页面收到失败结果
   - **那么** 页面显示中文错误提示和可执行的重新加载操作
   - **并且** 页面保留用户当前的关键词和状态条件

3. **快速连续修改条件**
   - **假如** 用户在请求尚未返回时连续修改查询条件
   - **当** 多个请求以不同顺序返回
   - **那么** 页面最终显示最后一次查询条件对应的结果，不得被较早请求的结果覆盖

## 3. 业务规则与查询要求

- 搜索字段仅为 Todo 标题，不搜索完成状态、创建时间或更新时间。
- 关键词去除首尾空白后为空时，视为未设置关键词；不得因为空关键词返回错误。
- 非空关键词采用标题包含匹配；匹配英文字母时不区分大小写。
- 状态筛选只允许三种逻辑值：`all`（全部）、`active`（未完成）和 `completed`（已完成）。未提供时默认使用 `all`。
- 关键词条件与状态条件同时存在时使用逻辑 AND；两个条件都未设置时等同于既有的全部待办列表。
- 查询结果沿用既有排序：未完成待办在已完成待办之前；同一状态内按创建时间从新到旧排序。查询不改变待办数据。
- 搜索结果为空与系统读取失败是不同状态，界面必须分别呈现。
- 查询输入必须由后端校验；不支持的状态值必须返回一致的客户端可识别错误，不得静默当作“全部”。
- 查询默认不分页，以保持本迭代与现有列表一致；本迭代不定义分页、无限滚动或结果数量上限。若后续数据规模需要分页，应另行建立规格。

## 4. 功能边界

### 纳入本迭代

- Todo 标题的包含搜索，英文字母大小写不敏感。
- “全部 / 未完成 / 已完成”三种状态筛选。
- 搜索与状态筛选的组合使用、条件清除和无结果提示。
- 查询的加载、失败、重试和快速连续查询下的结果一致性反馈。
- 在当前结果中继续使用既有的新增、编辑、完成/恢复和删除操作。
- 后端查询 API 契约、输入校验以及 API 和 E2E 测试所需的验收覆盖。

### 不纳入本迭代

- 按创建时间、更新时间、标题字母顺序或其他字段排序。
- 多关键词布尔表达式、正则表达式、模糊度评分、分词、高亮和搜索历史。
- 标签、优先级、截止日期、分类、多个 Todo 列表或多用户隔离。
- 分页、无限滚动、导出、批量操作和离线搜索。
- 修改既有 Todo 的数据模型、写入规则或删除语义。
- 用户登录、权限管理以及针对不同用户的搜索结果隔离。

## 5. 非功能要求

### 技术与架构

- 前端必须继续使用 React 和 TypeScript；后端必须继续使用 Node.js 和 TypeScript；Todo 数据必须从 MySQL 读取。
- React 前端只负责查询控件、结果呈现、交互状态和调用 HTTP API，不得直接连接 MySQL。
- Node.js 后端负责查询参数校验、查询组合和 MySQL 访问；数据库访问必须经过数据访问层，并使用参数化查询或 ORM 参数绑定，防止 SQL 注入。
- 搜索与筛选能力必须通过版本明确的 HTTP API 提供。后续计划必须定义方法、路径、查询参数、成功响应、错误响应和状态码；不得以修改既有写入接口语义替代查询契约。
- 前后端共享或生成查询相关的数据类型和错误结构；不得使用 `any`、无约束类型断言或忽略 TypeScript 错误。

### 性能与可靠性

- 在项目既有的常见 Todo 数据规模下，用户提交查询后应在可接受的交互延迟内得到结果；查询不得阻塞其他用户操作或破坏已保存数据。
- 数据库查询必须只返回符合关键词和状态条件的结果，并使用安全的参数绑定；不得通过拼接用户输入生成 SQL。
- 当查询失败时，错误响应不得泄露数据库凭据、SQL 语句或内部堆栈信息。
- 查询结果必须反映服务器当前已确认的数据；前端不得把本地临时过滤结果当作持久化查询的唯一来源。
- 快速连续查询不得造成过期响应覆盖最新条件对应的结果。

### 体验、可访问性与文档

- 搜索框、状态筛选控件、清除操作、加载状态、无结果状态和错误重试操作均应提供清晰的中文文本。
- 查询控件和结果操作必须支持键盘使用；控件应有可访问名称，加载和错误状态应能被辅助技术感知。
- 在常见桌面和移动浏览器可视区域内，搜索控件和待办结果不应依赖水平滚动。
- 项目规格、计划、任务、面向开发者的错误说明和新增代码注释必须使用中文。

### 测试与交付门禁

- 后续实现必须为查询 API 提供自动化测试，覆盖：无条件查询、关键词匹配、大小写、首尾空白、三种状态值、组合条件、无结果、不支持的状态值和主要失败场景。
- 后续实现必须提供 E2E 测试，至少覆盖用户输入关键词、切换状态筛选、组合条件得到正确结果，以及清除条件恢复列表。
- 功能在相关 TypeScript 类型检查、API 测试和 E2E 测试通过前不得标记为完成。
- 本迭代不得提交环境变量、数据库凭据或其他敏感信息。

## 6. 成功标准

当用户能够在 Todo 页面按标题关键词搜索、按完成状态筛选并组合使用两个条件，页面能够正确呈现加载、无结果和失败重试状态，查询结果来自后端 MySQL 且既有 Todo 操作仍按原规则工作，并且相关类型检查、API 测试和 E2E 测试通过时，本迭代满足交付条件。
